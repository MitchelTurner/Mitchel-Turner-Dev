What gets set up

One account. The pieces that have to stay up.

This is the setup I use for an application, not a catalog of every Amazon product. Each piece is something you can find in the console after handover.

01

An account in your name.

You open the AWS account, or we use one you already have. Billing, the root user, and the ability to remove my access stay with you. I work as a user on that account.

02

Amazon EC2

The application runs on a virtual server you can see in the console, sized for the traffic you actually have.

03

The database

PostgreSQL lives in the same account as the app, so the records and the software move together.

04

A path to ship a change

There is a written way to put a new version on that server. The next person does not rebuild it from old email.

05

The name and the lock

Your domain points at that server, and the site is served over HTTPS. The certificate and the DNS records are part of the handover.

06

A map you keep

What is running, which region it is in, how to sign in, how to deploy, and what a quiet month costs.

Straight answer

A brochure site does not need a virtual server.

Four pages and a contact form are a simpler hosting job, and that is how the web design work is set up. Amazon Web Services is for software with logins, a database, or a tool your crew opens every morning: bookings, billing, a record that has to still be there next season.

If a smaller host does that job for less, I will say so before anything is created in an account.
